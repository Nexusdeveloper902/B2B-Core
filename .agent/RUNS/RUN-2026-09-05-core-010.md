## Root cause (verified against vendor source, not guessed)

- `bootstrap/app.php` uses `$middleware->statefulApi()` → the api group
  prepends `Laravel\Sanctum\Http\Middleware\EnsureFrontendRequestsAreStateful`.
- That middleware's `fromFrontend()` matches the request's Referer
  (or Origin) host against `sanctum.stateful` (Str::is wildcards).
- Default stateful (config/sanctum.php):
  `localhost,localhost:3000,127.0.0.1,127.0.0.1:8000,::1` + APP_URL
  (localhost:8000) — a phone's `http://192.168.1.6:8000/...` referer
  matches NOTHING → request treated as stateless → `auth:sanctum` finds
  no user → 401 "Unauthenticated", seconds after a successful web login.
- Desktop localhost worked because localhost:8000 IS in the default
  list (the owner's serve log shows the full arm+poll cycle working).

## Testing pitfall recorded (why the tests pin fromFrontend directly)

A full-stack session test cannot produce the honest pre/post
differential: within one test method the container, the auth guard and
the session store are shared across requests, so a logged-in user stays
authenticated on the API route even when the stateful middleware is
bypassed (in-memory guard user / shared session store). The
`fromFrontend()` level is where the behavior actually changes, so that
is what the tests pin.
