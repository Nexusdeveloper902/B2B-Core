# RUN-2026-09-12-core-039 — Realtime event toasts (spec §23)

Owner (chat, 2026-09-12), while bench-testing the RC522 reader in
PAIRING mode: "The toasts i asked for do not appear." (Their firmware
log — connect() errno 104 to the backend — turned out already solved on
their side; the remaining gap was real and mine.)

## Diagnosis
- The toast system itself was intact and loaded in the owner's own tab
  (PulseToast + CSS verified in their live page). Desk-action toasts
  (create/import/pairing/redeem) work.
- The real gap: the owner was exercising the READER. Tapping a card
  produced NO toast anywhere, because ADR-048's "ambient realtime
  updates NEVER toast" clause had excluded tap/recycling frames — a
  mis-reading of the productization spec, whose §23 explicitly requires
  "a relevant toast appears" for a card tap and for the EcoStation
  classification flow. A tap is an EXTERNAL event (nobody on the
  dashboard caused it) — exactly what the acknowledgment layer is for.

## Changes (ADR-050, narrowing ADR-048)
- **Admin dashboard**: every `realtime:tap` → info toast
  "«student» — «event label»" (localized `event_type_*` map via
  `Js::from`; `@use Js` added to the view).
- **Teacher dashboard**: CLASS_ATTENDANCE taps only (the desk's own
  rows/flip logic carries the rest) — same guard set.
- **EcoStation hub**: `validated` → info "Deposit classified —
  «material»" (+ student name as description); `points_awarded` →
  success "+N «unit» — «student»" through the existing
  `labels.pointsUnit` map.
- **Student hub** (own frames only): `points_awarded` → success
  "+N PTS — well recycled!" via new bilingual key `toast_points_earned`.
- Guards on every site: `document.hidden` stays silent; 2 s
  per-student(+type) cooldown collapses reader retry bursts; the stack
  cap (4) + auto-dismiss bound bursts. WS-replayed ROSTER frames still
  never toast (they replay the admin's own fetch-acknowledged actions —
  double-announce avoided).
- Unit-honesty guard caught my first draft hardcoding "PTS" in the
  ecostation view (ProductizationTest, working as designed) — the unit
  now rides `labels.pointsUnit` / a `points_unit` key everywhere.

## Verification
- Full suite: **453 passed / 3 skipped** (the one red during the work
  was the PTS honesty pin — fixed by using the localized unit, exactly
  what the pin exists for); `./run quality` PASS.
- Live proof on the real stack (MariaDB + WS + browser): a device
  endpoint tap (Bearer reader key, curl → event_id 4) arrived over the
  websocket and rendered in the live feed; a synthetic
  `realtime:tap` dispatch through the page's own handler produced a
  visible info toast ("Verificación en vivo — Entry") in the same
  page-side script that fired it (the first real-tap check missed only
  because the 4 s auto-dismiss lost the race against cross-tool
  latency — the feed row proved frame arrival).
