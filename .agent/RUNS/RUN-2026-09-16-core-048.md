## Follow-up: repeat taps did not beep
- **Found:** the owner's bench showed three `[OK]` taps of one card and
  no beep. The dev DB had one events row, so the other two were
  first-tap-counts duplicates, which write no row and produce no frame.
- **Also found:** socket counters showed the phone's connection going
  silent without a close around 16:59, and later a connection that
  opened and closed. The app was not continuously foregrounded, so no
  backend frame could be heard during those gaps.
- **Fixed:** the `tap_feedback` channel (see TASK-047).
- **Incident:** `artisan serve` loaded the new `TapService` before the
  dev migration ran, so one duplicate tap at 17:03:09 returned 500 (its
  transaction rolled back; duplicates write nothing). The dev DB was
  migrated immediately after, and the write was made best-effort.
