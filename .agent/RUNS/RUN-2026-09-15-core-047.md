# RUN-2026-09-15-core-047 — TASK-046 responsive panel fixes

## What was done
Measured instead of guessed: built a browser-based overflow probe, ran
all 17 panels at 15 widths (320 → 1600px), fixed what it found, re-ran
to green. Six CSS fixes, all structural:

1. `min-width: 0` on every layout container's items — the
   `min-width: auto` default was silently defeating the `overflow-x`
   scrollers the design already had.
2. `.filterbar` gets `flex-wrap: nowrap` in its column layout (a
   wrapping column flex container is a multi-column one).
3. `.filterbar .searchbox` drops its `flex-basis` in that column
   (`flex-basis` is the MAIN axis — 320px wide became 320px tall).
4. `.topnav` becomes the shrinking, self-scrolling element so the admin
   topbar stops pushing logout and EN/ES off-screen at 941–1400px.
5. `.stat-row` given a rule at all (auto-fit grid) — the PAE KPI tiles
   had no layout at any width.
6. `.ledger-wrap`'s edge bleed scoped to `.panel`, where the padding it
   cancels actually lives.

## Traps
- **Chrome headless has a minimum window width** (~485px here), so
  `--window-size=390` does NOT give a 390px layout viewport. Measuring
  inside a fixed-width iframe does.
- **`overflow: hidden` still reports a large `scrollWidth`.** The
  `.metric-hero` decorative blob (`right: -34px`, clipped by design)
  looked like a 34px overflow on every page until the probe learned to
  count only `overflow-x: visible`.
- **Something reformatted `public/css/app.css` wholesale mid-session**
  (+2151/−485 where the real change was ~130 lines), which also broke a
  CSS-pinning test that matches on the file's compact selector grouping.
  Restored from HEAD and re-applied every edit by hand in the file's own
  style. Worth watching: if it recurs, the pins in `DashboardTest` are
  the canary.
- A `.ledger-wrap` fix needs its `@media` counterpart updated too —
  `.panel .ledger-wrap` (0,2,0) beats a bare `.ledger-wrap` (0,1,0), so
  the mobile reset silently stopped applying until it was scoped to
  match.
