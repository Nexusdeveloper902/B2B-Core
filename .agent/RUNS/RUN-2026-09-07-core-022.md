## Summary
The recycling subsystem now implements the owner's spec on the backend:
atomic awards, the bottle-first state machine with expiry, image
persistence, a ledger-derived leaderboard, student self-service accounts,
committed-state recycling WS frames, the full rewards catalog model
(stock/active/type/value + redemptions + idempotency), and the AI
boundary schema. Design reused the repo's proven shapes: pending_captures
mirrors pending_pairings (TTL + clock-jump guard); recycling_updates
mirrors events-as-broadcast-source (append-only, transactional writes,
read-only WS poll); student accounts are a 1:1 users layer referencing
students (never a second identity).

## Discoveries
1. The first e2e attempt at student login failed with 419 Page Expired —
   session login requires the CSRF token; curl must fetch the login page
   and send _token like a browser. Fixed in e2e.sh.
2. Paginator gotcha: `$ledger->get()` on a LengthAwarePaginator forwards
   to Collection::get($key) — the blade history view crashed until
   switched to getCollection().
3. The duplicate-window heuristic initially blocked intentional repeat
   purchases in tests — resolved by design, not by test tuning:
   request_id-bearing clients get TRUE idempotency; the window only
   guards keyless clients (see ADR-034).
4. Runner reminder (matches audit-002 Discovery #3): running phpunit
   with .tools/ in PATH pollutes ScriptSuiteTest's PATH-probing test —
   always use ./run test (it resolves PHP without PATH mutation).

## Decisions
- ADR-031: bottle-first persists via pending_captures (pending_pairings
  pattern: TTL, clock-jump guard, lazy sweep on write paths only).
- ADR-032: recycling WS frames come from a transactional append-only
  recycling_updates table (commit-only broadcast; WS server stays
  read-only).
- ADR-033: student accounts are a 1:1 users.student_id layer — students
  rows stay the single identity.
- ADR-034: redemption double-submit protection = request_id idempotency
  + time-window fallback for keyless clients.
- ADR-035: leaderboard derives exclusively from points_ledger with
  competition ranking; every student ranks (zero-movement = 0).
