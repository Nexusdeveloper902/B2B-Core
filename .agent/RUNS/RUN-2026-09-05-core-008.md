## Discoveries

- The first `composer install` on a fresh vendor tree runs
  `@php artisan package:discover` against a partial vendor state and
  fails with "Target class [config] does not exist" — a second run (or a
  manual `php artisan package:discover`) succeeds; the vendor tree ends
  complete and functional. Environment quirk, not a repo defect; CI
  runners with proper PHP are unaffected.
- PHP toolchain for this sandbox: system PHP is absent and sudo is not
  available, so PHP 8.4.24 was provisioned via `apt-get download` +
  `dpkg-deb -x` into a user-owned tools dir and exposed to the ./run
  suite through the `B2B_PHP` resolution chain (which worked exactly as
  ADR-010 designed it — no PATH hacks needed). Not a repo change; noted
  here because the next agent in this sandbox will need the same trick.

## Decisions

- ADR-020 (two-step arm-then-pair, 45 s window, reader-key auth on the
  pair side, never-reassign, most-recent-wins).
- paired_student_name returns the student's FULL name (tap's
  student_first_name remains first-name-only): pairing feedback is the
  operator confirming identity, where the full name is the safer string.
