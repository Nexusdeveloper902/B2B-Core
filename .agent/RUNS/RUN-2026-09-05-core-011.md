# RUN-2026-09-05-core-011 — unpair-every-card testing script (TASK-013)

Owner's request (verbatim): "ok you should make a little script in b2b
core that basically unpairs every card (itll make testing easier), same
protocol."

## Context
Pairing works end-to-end on the bench since B2B-Firmware TASK-007 +
B2B-Core TASK-012. But ADR-020 invariant 2 burns every credential on
first successful pair (any existing cards row → 422 forever), so each
pairing bench pass needed a manual row delete. This run gives that reset
one guarded command, following the ADR-009 run-suite architecture.

## What was built
- `app/Console/Commands/UnpairCardsCommand.php` — `cards:unpair
  {--force}`: deletes every `cards` row inside ONE transaction, children
  first (all `events` — every event belongs to a card; then
  `pending_pairings.card_id` cleared — history rows survive), so the
  outcome is deterministic even where the sqlite FK pragma is off.
  Bilingual warn/confirm/result output with honest counts; empty table
  is a clean noop. Semantics fixed by ADR-023: unpair = DELETE (a
  student_id-nulling "unpair" would leave the row blocking re-pairing —
  a fake unpair).
- `scripts/unpair.sh` + `./run unpair` — reset.sh-style wrapper: same
  guard pattern (bilingual warning + confirm unless `--force`), then
  `"$PHP_BIN" artisan cards:unpair --force`. Wired into the dispatcher's
  `script_for` map + bilingual usage text.
- `tests/Feature/Console/UnpairCardsCommandTest.php` — 5 tests: (1) full
  semantics vs a seeded + paired + tapped DB (cards 0, events 0,
  history links 0, history rows > 0, students/readers/users unchanged);
  (2) THE BENCH LOOP — pair `62041607` to student A, second pair attempt
  422s, `cards:unpair --force`, the SAME uid pairs to student B with a
  clean event history; (3) the confirmation guard both ways
  (expectsConfirmation no → nothing changes; yes → deletes); (4)
  bilingual output with exact counts + the `./run reset` tip; (5)
  empty-table noop (both paths).
- `ScriptSuiteTest` COMMAND_SCRIPTS + `unpair` → suite invariants now
  cover the new command (existence, +x, dispatch, help listing, docs
  parity, bash -n, no-bare-php); its data provider adds one case.
- Docs: `docs/SCRIPTS.md` + `SCRIPTS.es.md` `## unpair` sections with
  the deletes/keeps table; `.agent/ARCHITECTURE/card-pairing-flow.md`
  gained "Re-testing the flow (TASK-013, ADR-023)" explaining why the
  reset is needed (invariant 2) and what it does.
- `.agent` records: ADR-023, TASK-013, this RUN + ledger, STATE
  snapshot, PROJECT.md facts.
