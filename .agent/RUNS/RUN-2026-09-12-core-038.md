# RUN-2026-09-12-core-038 — SQLite → MariaDB migration

Owner (chat, 2026-09-12): "Migrate to mariadb please."

## What was done
- **Server provisioning (this workstation)**: the system MariaDB 12.3
  is active but root-only (unix_socket auth, no root for the agent), so
  Pulse runs on a USER-LEVEL instance: `~/.config/systemd/user/
  pulse-mariadb.service` → datadir `~/.local/share/pulse-mariadb`,
  socket `$XDG_RUNTIME_DIR/pulse-mariadb.sock`, TCP 127.0.0.1:33060
  (loopback-only), enabled with linger (durable across reboots).
  Databases `pulse` (app) + `pulse_test` (suite), user `pulse` with a
  generated password stored ONLY in `.env`.
- **App switched**: `.env` → DB_CONNECTION=mariadb; migrations + seed
  ran clean on the first pass (ADR-001's portability claim verified);
  sessions/cache tables now live in MariaDB.
- **Six engine-truths fixed** (first MariaDB suite run: 447/453):
  1. REAL PRODUCT BUG — `roster_updates.payload` `text` = 64 KB ceiling
     on MariaDB; a bulk CSV import broadcast exceeded it (SQLSTATE
     22001 → HTTP 500 mid-import). New migration
     `2026_09_12_000001_widen_roster_updates_payload_to_json` → `json`
     (LONGTEXT). Applied to the dev DB (column now longtext).
  2-5. Four positional-id test fixtures (`class_id => 1`, `'reader_id'
     => 1` ×2, `assertSame(1, RealtimeToken::verify())`, token regex
     `1\.`) — InnoDB auto-increment survives rolled-back transactions
     (SQLite rowids don't), so seeded rows are no longer id 1.
     Fixed by named-fixture lookups (RUN-033's rule, now engine-proven).
  6. UnpairCardsCommandTest simulated "DB not ready" with a bare
     `Schema::drop('cards')` — MariaDB refuses drops on schema-level FK
     grounds even when empty; now wraps the drop in portable
     disable/enable FK constraints.
- **Run suite driver-aware** (ADR-049): `mariadb_probe` +
  `mariadb_remediation` helpers in common.sh (credentials travel as
  process env to the PHP child — never argv, never echoed);
  `./run setup` probes before migrating; `./run serve` probes instead
  of the sqlite file check (mariadb previously FELL INTO the file
  check and would have died); `./run reset` runs the guarded
  migrate:fresh on MariaDB (verified live with `--force`); `./run
  status` reports the live target; `./run doctor` checks pdo_mysql +
  reachability + schema depth (verified: 23 tables).
- **CI**: new `mariadb` job — MariaDB 12 service container + FULL suite
  (mirrors the local proof). The ScriptSuiteTest drift guard caught the
  extension it installs → two-tier module contract:
  `PHP_RUNTIME_EXTRA_MODULES=(pdo_mysql)` enforced by doctor only under
  the mariadb driver, out of interpreter candidate filtering
  (hermetic-toolchain path unaffected); drift test covers both tiers.
- **e2e pinned hermetic**: `DB_CONNECTION=sqlite` exported explicitly
  (an unpinned connection would have pointed `database/e2e.sqlite` at
  the MariaDB server).
- **Docs**: `docs/DATABASE.md` + `.es.md` (engine contract, provisioning
  SQL, instance layout, CI, timezone); SCRIPTS.md + .es.md updated
  (setup/reset/troubleshooting); ADR-049.

## Decisions
- ADR-049 (supersedes ADR-001's storage choice): MariaDB = product
  storage; SQLite stays the engine of the test suite, the e2e and the
  zero-config fresh clone; CI runs the suite on BOTH engines.
- Marketplace NOT touched (stateless by design, its ADR-013); Firmware
  has no database.
