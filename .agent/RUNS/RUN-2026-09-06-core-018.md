## Implementation (ADR-029)

- `PairingService::arm()` — single-window invariant (same-transaction
  close of every other active window); `pair()` retires lingering
  pre-invariant rows.
- `PendingPairing::scopeActive()/isActive()` — clock-jump guard
  (`created_at <= now()`); desk JS clamps the arm-response countdown
  to the configured window; the desk ticker finalizes expiry locally.
- `PairingService::statusPayload()` — the ONE truth; the REST status
  endpoint and the realtime pairing frames serialize it identically.
- `RealtimePairing` (new) — md5 signature over mutable
  pending_pairings columns + the shared payload.
- `realtime:serve` — polls the signature on the same beat; arm /
  consume / reject changes broadcast `{"type":"pairing", …}` to
  ADMIN connections only (role resolved once per connection, fail
  closed — pairing frames carry card UIDs, tap frames never do);
  hello carries the pairing snapshot for admins.
- `realtime.js` — one client, two pages: any `[data-realtime]` boot
  node, feed rendering gated on `#live-list`, `realtime:pairing`
  CustomEvent.
- Pairing desk page — same badge grammar, SSR-minted token
  (AdminPairingController), desk script applies frames through the
  same `applyStatus()` its poll uses; poll kept as honest fallback.
