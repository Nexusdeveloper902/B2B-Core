## 3. Problems found & fixed

### P0 — Mobile users could not log out
`app.css` ≤620 px rule `.topbar-tools .inline-form { display:none }` was meant
to hide the topbar logout **button**, but the hamburger menu lives inside
`.topbar-tools` too — its logout form was hidden with it. On a phone there was
**no way to sign out at all**.
**Fix:** scope the rule to the direct child (`.topbar-tools > .inline-form`).
**Pinned:** `StudentAccountTest::the_mobile_menu_keeps_the_logout_form_reachable`.

### P0/P1 — Tall sections rendered invisible while scrolling
The scroll-reveal trigger (anime.js `onScroll`, `enter: '85% center'`) fired
when an element's **center** crossed a line near the viewport bottom. A panel
taller than the viewport (teacher dashboard class ledger ≈1100 px, students
desk roster on phones) stayed at `opacity: 0` — a blank page — until the user
scrolled past its middle.
**Fix:** `motion.js` now uses an `IntersectionObserver` (threshold 0, bottom
rootMargin −10 %): any part of an element entering the viewport reveals it.
anime.js still drives the stagger animation; `.js-motion` gating and full
`prefers-reduced-motion` respect are unchanged.
**Pinned:** `DashboardTest::the_layout_gates_motion_and_loads_the_reveal_module`
(updated pin: same architecture contract, new trigger).

### P1 — Logged-in students hitting /login landed on a bare 403
The framework default redirect for authenticated users on guest-only pages
sends everyone to `/dashboard` — staff-only. A student opening a bookmarked
`/login` got Laravel's raw abort page: no shell, no nav, no logout.
**Fix:** role-aware `redirectUsersTo` in `bootstrap/app.php` (students →
`student.dashboard`, staff → `dashboard`).
**Pinned:** `StudentAccountTest::a_logged_in_student_opening_a_guest_page_lands_on_their_own_dashboard`.

### P1 — Error pages were dead ends (and guest-mode English)
403/404 rendered Laravel's bare abort output. Worse, an unmatched path renders
**before** the web middleware runs, so even logged-in users saw a guest-mode,
English-only page regardless of session or locale.
**Fix:**
- New `resources/views/errors/{403,404,500,503}.blade.php` (+ shared
  `minimal.blade.php`): rendered inside the app shell — topbar nav, footer,
  honest copy (EN/ES via `lang/`), and a role-aware way out
  ("Back to your dashboard" / "Go to sign in").
- `Route::fallback` in `routes/web.php` so unknown **web** paths render that
  view through the full middleware (session, locale, auth). The fallback
  rebuilds the router's own verdicts: a known path probed with the wrong
  verb still returns **405 with Allow**, and unknown **API** paths still
  return the byte-identical JSON 404 (same exception message under
  APP_DEBUG).
**Pinned:** `StudentAccountTest::access_denied_renders_inside_the_app_shell_with_a_way_out`.

### P2 — Horizontal page scroll on phones (both apps)
`1fr` grid/flex tracks honor the item's min-content. Core's students-desk CSV
`<input type="file">` (large intrinsic min-width) plus panel padding pushed a
`grid-2` track to 386 px inside a 375 px viewport — the whole page scrolled
sideways. Marketplace had the same class of bug from the other side: `.widget`
combines `width:100%` with padding under `content-box` (+38 px), the hero
demo ledger table was nowrap-uncontained, and the mobile header kept the
desktop CTA *and* the "Menú" label (see §9).
**Fix (Core):** `.grid-2 > * { min-width: 0 }` + `min-width:0; max-width:100%`
on the file input. Verified: `scrollWidth == clientWidth` at 390 px.
**Fix (Marketplace):** `.bento > * { min-width: 0 }`, `box-sizing: border-box`
on `.widget`, a `.ledger-wrap` scroll container around the hero demo table.

### P2 — EcoStation "Total awarded to students" contradicted the students
The hero metric summed `recycling_deposits.points_awarded` (10 PTS in demo
data) while every student-facing surface (balances, standings board — and the
class standings panel) sums the **points ledger** (25 PTS). Two pages told
different stories about the same fact.
**Fix:** `AdminDashboardController::ecostation()` now sources `totalPoints`
from `PointsLedger::sum('delta')` — the same source `PointsService` uses for
balances. Realtime frame bumps stay compatible (each award writes a ledger
row). The admin dashboard's "Points awarded" KPI is intentionally unchanged:
it is today-scoped next to today's ITEMS metric.
**Pinned:** `MockupPagesTest::the_ecostation_hub_renders_for_admins_only`
(extended: a ledger row without a deposit twin must move the hero, and the
+15 METAL rate row must not satisfy the assertion).

### P4 — Parent timeline empty state spoke twice
With zero events the panel showed both "No events recorded yet for this
student." **and** "No records match the selected criteria." (the filtered
variant's copy). The filter line now renders only when rows exist but
pills/search hide them all.

## 4. Investigated and deliberately NOT changed

- **Marketplace package-counts bars** (Cards 200 → short bar, Apps 1 → longer
  bar): the bars scale **across tiers within a row** (12 % @ Starter → 100 %
  @ Enterprise), which is internally consistent with the published packages;
  the widget note states the source. Changing the encoding would be a
  redesign decision, not a polish fix.
- **Login demo-credentials block appearing faint in early screenshots**: that
  is the reveal animation mid-flight, not low contrast (computed opacity 1,
  dark-on-white after settle).
- **Students desk placeholder-only inputs**: every control carries an
  `aria-label`; the single-row desk grammar comes from the owner's mockups.
- **"Bienvenido" gender forms**: the greeting is not gendered in the data
  model; adding grammatical gender would need new schema, out of scope.
- **Rewards hero / EcoStation column balance**: whitespace asymmetries at
  some widths; touching them risks over-polish (§30 of the brief) with no
  usability gain.
- **Realtime OFFLINE duplication** (chip + footer note): two placements serve
  two scroll positions; harmless and honest.
