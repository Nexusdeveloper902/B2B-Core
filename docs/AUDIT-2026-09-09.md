## Executive summary

The platform was already in strong shape (328 baseline tests green, Pint
clean, careful transaction/race handling throughout the services). This
audit pass found and fixed the defects that remained — concentrated in
three bands: (1) security edges no legitimate user hits but a hostile input
or an orphaned account would (fail-open student scope, unthrottled
brute-forceable login, inline-script JSON escaping, an unbounded WS
handshake buffer), (2) a handful of real correctness bugs (running balance
wrong after the first history page, mobile filters defeated by CSS, the
NL tool loop exceeding its documented bound), and (3) documentation drift
where docs described retired designs and wrong semantics.

## Remaining recommendations

1. Reader API keys are stored plaintext in `readers.api_key` (documented
   ADR tradeoff); hashing them is the next security step if the backend is
   ever exposed beyond a school LAN.
2. Admin dashboard loads the full student table for selects/quick links —
   paginate the quick links if a school exceeds a few hundred students.
3. The students (name, class) duplicate check is check-then-insert; two
   simultaneous admin creates can race. An explicit unique index is NOT
   recommended (real schools have same-name classmates) — the 422 desk flow
   is the right UX; this note exists so the choice is documented.
4. The `resources/css+js` + Vite toolchain is unused (Blade links
   `public/css`+`public/js` directly); removing it would also drop the
   npm steps from `composer run setup`. Deliberately left in place here —
   removal touches the build story, which the owner may want to decide.
