## Resumen ejecutivo

La plataforma ya estaba en muy buen estado (328 pruebas base en verde, Pint
limpio, manejo cuidadoso de transacciones/carreras en todos los servicios).
Esta pasada de auditoría encontró y corrigió los defectos que quedaban,
concentrados en tres bandas: (1) bordes de seguridad que ningún usuario
legítimo toca, pero sí una entrada hostil o una cuenta huérfana (scope de
estudiante que fallaba ABIERTO, login sin throttle, escaping JSON en
scripts inline, buffer de handshake WS sin límite), (2) varios bugs reales
de corrección (saldo corrido mal tras la primera página de historial,
filtros móviles vencidos por CSS, el bucle de herramientas NL excediendo su
límite documentado), y (3) documentación que describía diseños retirados y
semánticas incorrectas.

## Qué cambió (verificado por la suite: 329 aprobadas / Pint limpio)

| Área | Cambio | Por qué |
|---|---|---|
| Auth | `POST /login` con throttle de 6/min por IP (`throttle:login`) | guarda anti fuerza bruta |
| Costo API | `POST /api/v1/nl-query` con throttle de 20/min por usuario | cada llamada es un viaje LLM pagado |
| Muro de datos | `StudentScope::forUser()` + `resolveScope()` del WS fallan CERRADOS para cuentas de estudiante con `student_id = null`; las páginas del estudiante responden 404 en vez de fatalear | una cuenta huérfana recibía antes frames de toques de toda la escuela |
| WS realtime | tope de 32 KB al buffer pre-handshake; `isAdmin()` muerto eliminado | superficie de memoria sin límite / código muerto |
| BD | SQLite `busy_timeout=5000` + journal WAL | 500s por colisión de bloqueo poller-vs-escritor |
| Puntos | replay de `request_id` acotado por estudiante; la carrera de UNIQUE se convierte en replay/duplicate | sin fuga entre estudiantes, sin 500 en envíos idempotentes concurrentes |
| Bucle NL | máximo real de 3 rondas de herramientas | el docblock decía 3, el código permitía 4 |
| Clasificador | driver desconocido → 503 `classifier_unavailable` | antes era un 500 sin manejar |
| `cards:unpair` | docblock/SCRIPTS ahora declaran que los depósitos cascan con los eventos + imágenes borradas (archivos eliminados y contados); prueba que lo fija | la doc antes decía "reciclaje intacto" |
| Frontend | saldo corrido sembrado con el saldo heredado; `tr[hidden]` vence al CSS apilado; la prop `rule` del panel renderiza; las cajas NL cierran aria-live al fallar; contador de la línea de tiempo con plantilla + nota de filtro vacío; filas vivas con `data-label`; `PTS` → `app.points_unit`; login con `aria-describedby`; el hero `is-first` del leaderboard sigue al re-sort en vivo; feedback de modo del lector en su propia región viva | corrección + móvil + accesibilidad |
| Escaping | scripts inline de los escritorios usan `Js::from()` | literales JSON seguros por hex-tags |
| Docs | README EN/ES describen el sistema real "Datum"; conteo e2e 22→30 en SCRIPTS; `unpair` añadido a la tabla de comandos; docs FRONTEND listadas en la estructura del repo | la documentación debe describir el sistema real |

## Recomendaciones restantes

1. Las claves API de los lectores se guardan en claro en `readers.api_key`
   (tradeoff documentado en ADR); hashearlas es el siguiente paso de
   seguridad si el backend se expone más allá de la LAN de la escuela.
2. El dashboard admin carga la tabla completa de estudiantes para los
   selects/enlaces rápidos — pagina los enlaces rápidos si la escuela pasa
   de unos cientos de estudiantes.
3. La verificación de duplicados (nombre, clase) es check-then-insert; dos
   creaciones admin simultáneas pueden competir. NO se recomienda un índice
   único explícito (en escuelas reales hay compañeros homónimos) — el flujo
   422 del escritorio es la UX correcta; esta nota existe para documentar la
   decisión.
4. El toolchain `resources/css+js` + Vite no se usa (Blade enlaza
   directamente `public/css`+`public/js`); eliminarlo también quitaría los
   pasos npm de `composer run setup`. Se dejó en su lugar a propósito —
   su eliminación toca la historia de build, una decisión del dueño.
